- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work.
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report.
- 2026-11-19: Added `weather_severity_lag_1` (yesterday's weather severity), following the `/new-feature` skill steps (agent: Claude Opus 5.5 in Claude Code, not the local bikeshare-coder). Availability: the weather on d-1 is recorded before d, and it is shifted on the reindexed calendar so the day after the 2011-03-10 gap is NaN, not d-2. Rationale: a BAD day depresses `cnt_lag_1`, so the lag under-predicts the day after. Validation R^2 ridge 0.6475 -> 0.6670 (+0.0195), hgb 0.2185 -> 0.2437 (+0.0252); valid MAE ridge 832.9 -> 803.9. Above the 0.01 noise threshold, so KEPT. Test set not consulted.

- 2026-11-19: Exercise 4, pre-registered before any run. hgb cannot predict above the 2011 maximum (6,043), so a target transform helps only if it removes the level. Candidates: A `log(cnt)` (control, still capped), B `cnt - cnt_lag_1`, C `log(cnt / cnt_roll_7)`, D residual from a linear time trend fit on 2011. B and C take their level from past demand known at prediction time; D gets past the cap by assuming the 2011 growth line continues, the same bet `src/config.py` rejects for time-index features. Selection rule: best validation R^2 among B and C; test scored once, for that one only. Disclosure: C is the target the teammate repo used; I saw it in the Exercise 3 audit before choosing.
